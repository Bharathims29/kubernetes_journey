1 System Architecture

A single Ingress entry point fans traffic into three tiers — frontend, backend, and data — all inside the demo-app namespace.

💡 Key insight: the Ingress /api rule is more specific than /, so API traffic never falls through to the frontend. The backend reaches MongoDB by the Service DNS name mongodb, not a Pod IP.

🔒 Startup behavior: await mongoose.connect(...) happens before the HTTP server listens. If Mongo isn't reachable the container crashes and Kubernetes restarts it — a deliberate fail-fast design.
  • StatefulSet (not Deployment) → stable pod name mongodb-0 and a stable PVC
  • Readiness probe authenticates via mongosh → not just a TCP check
  • Liveness probe uses a TCP socket check → port :27017 reachable
  • Root user created on first boot → from mongodb-credentials Secret

6 Configuration & Secrets Flow

The backend gets everything from process.env. ConfigMap and Secret both get injected via envFrom — one string, one credentials.

Why split ConfigMap and Secret?

🗺️
ConfigMap
Holds the connection string — non-sensitive, safe to view/commit.
🔐
Secret
Holds the credentials — base64-encoded at rest, consumed by both Mongo (root user) and backend (auth).
🧩
No inline password
Mongoose connect(uri, { auth: {...} }) — password is never embedded in the connection string itself.

7 Health Check & Probe Flow

Each pod uses readiness + liveness probes. The backend probes hit /api/health — the exact same route server.js defines.

PodProbeCheckFailure behavior
Backend readinessGET /api/health 503 → removed from Service endpoints
livenessGET /api/health 503 → Pod restarted
Frontend readinessGET / Non-200 → no traffic routed
livenessGET / Non-200 → Pod restarted
MongoDB readinessmongosh ping (auth) Auth failing → no traffic routed
livenessTCP :27017 Port closed → Pod restarted
🩺 MongoDB's readiness probe actually authenticates (db.adminCommand({ping:1})) rather than just checking the port — Kubernetes won't route traffic to Mongo until auth is genuinely working.

8 Local Dev vs Cluster Comparison

Same code, different wiring. The frontend and backend never branch on environment — only the infrastructure around them changes.
